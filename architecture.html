Lele architecture

A Rust workspace: a zero-domain micro-kernel, pure port contracts, independent packages, and one TUI frontend that is also the composition root. Surface from contracts.inspect; wiring from crates/frontends/lrs/src/backend/local.rs.

1 · Crates

Each box is a crate. Every package depends only on protocol and sdk (plus support/*); lrs is the only crate that sees packages.

4 · One turn, end to end

From pressing enter to the answer on screen, local backend. The runtime holds no agent logic: it resolves ports, persists, and relays events.

sequenceDiagram
  autonumber
  participant U as User
  participant App as lrs App
  participant LB as LocalBackend
  participant JM as JobManager
  participant SS as SessionStore
  participant R as Runner (react)
  participant GW as ModelGateway
  participant EX as ToolExecutor
  participant P as Permission

  U->>App: enter
  App->>App: expand paste chips, echo prompt
  App->>LB: start_run(RunRequest)
  LB->>JM: start_run(session, cwd, text, model, effort)
  JM->>JM: resolve runner, gateway, executor, permission, presentation
  JM->>SS: push(User, text)
  JM->>SS: history(session)
  JM-->>LB: job_id (turn runs on its own thread)
  LB-->>App: RunResponse
  App->>LB: stream_events(job_id)
  loop until the model stops calling tools
    R->>GW: stream(model, system + history, tool definitions)
    GW-->>R: Chunk: TextDelta / Thinking / ToolCallChunk / Usage / Done
    R-->>App: Event::TextDelta (live tokens)
    opt tool calls
      R->>EX: dispatch(call, args)
      EX->>P: permission(tool, args)
      P-->>EX: allow / deny
      EX-->>R: ToolOutput (rendered by presentation for the model)
    end
    R->>JM: Event::MessageAdded (assistant, tool results, steers)
    JM->>SS: append(message) via RecordingSink
  end
  JM-->>App: Event::JobFinished / JobFailed
  1. Fail closed. No permission policy registered means no turn starts; no presentation means no turn starts.
  2. Persist then forward. RecordingSink stores each MessageAdded before clients see it, so the next turn replays exactly what the model saw.
  3. Steering. Text typed mid-turn goes to TurnController::steer; the runner injects it at a safe point.

5 · Keyboard and paste

The Windows console has no bracketed paste: a paste arrives as one key event per character, newlines as enter. The loop drains everything queued every 30 ms and decides per batch. Step ② is today's fix: mouse moves landing between pasted characters used to make the batch "not text", so every pasted newline ran as enter and each line was sent as its own message.

flowchart TD

crossterm event::read()"] --> ch[["channel"]]
  ch --> poll["poll: drain up to 4096 events"]

  poll --> inert["② drop inert events

then handle each event"]
  flush -->|"typing: next tick

  force --> lp{"looks_pasted?
≥8 chars or newline mid-text"}
  lp -->|"yes"| paste["paste(): CRLF/CR → LF
image paths → attachments

  lp -->|"no"| typed["replay as keystrokes

  1. AltGr is text. Italian layouts encode { } [ ] @ # as ctrl+alt; only ctrl without alt counts as a chord.
  2. Images. ^p (and ^v where the terminal lets it through) reads the clipboard image via arboard; a pasted file path or file:// URL becomes an [Image #N] chip.
  3. Panic safety. A panic on the main thread now restores the terminal (raw mode, mouse capture, alternate screen) before the message prints.

6 · Known gaps

Images stop at the local backend. The app builds OpenAI-style content parts, but LocalBackend::start_run accepts text only, SessionMessage has no attachment field, and the gateway sends content as a string. protocol::RunRequest.images is unused. Images work only with --backend http.
Direct Anthropic provider format. The anthropic endpoint posts an Anthropic-format body to /chat/completions with a Bearer header, and its stream parser ignores tool_use blocks. An anthropic/… model works only through OpenRouter, that is, while no direct anthropic key is connected.
